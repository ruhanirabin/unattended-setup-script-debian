# Plan: Enhance Unattended Setup Script for Reliability, Compatibility & Professional Quality

## Overview

Comprehensive refactor of `setup_auto_updates.sh` to improve reliability, error handling, and compatibility across Ubuntu 24/25/26 and Debian 13+, while adding comprehensive logging, a VERSION variable, MIT license, and updated documentation.

---

## Phase 1: Core Script Rewrite (`setup_auto_updates.sh`)

### 1.1 Single Source-of-Truth VERSION Variable
- Add `VERSION="3.0.0"` at the top of the script as the **only** version definition
- All version references (header, output, logging, GitHub workflow) will derive from this single variable
- Remove hardcoded `2.4.3` from all locations in the script and README.md

### 1.2 Comprehensive Logging System
- Add a logging subsystem with functions: `log_info()`, `log_warn()`, `log_error()`, `log_debug()`
- All output goes to stdout AND to a log file at `/var/log/unattended-setup.log`
- Log format: `[YYYY-MM-DD HH:MM:SS] [LEVEL] message`
- Add `--verbose` and `--log-file <path>` CLI flags
- Capture apt/dpkg output into the log for troubleshooting

### 1.3 Graceful Error Handling
- Replace `set -e` with a custom error handler via `trap err_handler ERR`
- Each critical function returns exit codes instead of calling `exit 1` directly
- Add `cleanup()` trap on EXIT to handle partial states
- Errors are logged and displayed with actionable guidance (e.g., "Run `journalctl -u unattended-upgrades` for details")
- Non-critical failures (e.g., dry-run test on minimal systems) produce warnings instead of aborting

### 1.4 Distribution Detection (Ubuntu 24/25/26 + Debian 13+)
- Robust detection using `/etc/os-release` with fallbacks
- Extract: `ID`, `VERSION_ID`, `VERSION_CODENAME`, `UBUNTU_CODENAME` (for Ubuntu)
- Validate supported versions:
  - Ubuntu: 24.04, 24.10, 25.04, 25.10, 26.04, 26.10
  - Debian: 13+ (trixie, forky, sid)
- Display clear error with supported versions list when unsupported

### 1.5 Fix Configuration Conflicts (Critical Bug Fix)
**Current issue:** The script writes both `50unattended-upgrades` AND `20auto-upgrades` AND `10periodic`, which causes APT config conflicts and redundancy.

**Fix:**
- Write only `/etc/apt/apt.conf.d/50unattended-upgrades` and `/etc/apt/apt.conf.d/20auto-upgrades`
- Remove the redundant `10periodic` file (settings are duplicated in `20auto-upgrades`)
- Use the correct config syntax per distro:
  - **Ubuntu:** `Unattended-Upgrade::Allowed-Origins { ... }`
  - **Debian 13+:** `Unattended-Upgrade::Origins-Pattern { ... }` (different syntax)
- Add `Unattended-Upgrade::AutoFixInterruptedDpkg "true"` for reliability
- Add `Unattended-Upgrade::MinimalSteps "true"` for resilience against interruption
- Add optional auto-reboot configuration (disabled by default, documented)

### 1.6 CLI Flags / Non-Interactive Mode
- Add `--yes` / `-y` flag to skip all prompts (for automation/Ansible/Packer)
- Add `--dry-run` to only validate without making changes
- Add `--help` / `-h` for usage info
- Backward compatible: running without flags behaves like current interactive mode

### 1.7 Remove Decorative Elements That Hide Errors
- Remove `> /dev/null 2>&1` from apt-get commands (errors must be visible and logged)
- Remove the animated progress bar (it obscures real output and breaks CI/CD)
- Replace `clear` with an info banner

### 1.8 Backup Existing Configuration
- Before writing any config file, back it up to `/etc/apt/apt.conf.d/<file>.bak.<timestamp>`
- Report backup locations to the user

### 1.9 Post-Setup Verification
- Verify service state after enable/start
- Show `journalctl` excerpt if service fails
- Provide a summary of what was configured

## Key Tradeoffs & Decisions

- **VERSION variable:** Using a simple `VERSION="3.0.0"` string (not semver parsing in bash) keeps it lightweight and compatible
- **Removed apt-listchanges:** This package is optional and not needed for the core functionality; reduces install time and potential conflicts
- **10periodic removal:** The settings in `10periodic` are fully duplicated by `20auto-upgrades`; keeping both causes confusion
- **Debian config syntax:** Debian uses `Origins-Pattern` while Ubuntu uses `Allowed-Origins` — these are NOT interchangeable, this is a critical fix
